# SKILL: Agent 上下文交接 (Agent Context Handoff)

[English](SKILL.md) | [简体中文](SKILL.zh-CN.md)

## 描述
创建一个通用的、不绑定特定工具的跨 Agent 工程上下文交接规范包。触发后，将当前工作区的状态编译并输出到 `.agent_handoff/` 目录下。

---

## 🎯 触发唤醒词 (Trigger Words)
当用户在对话中发送以下任意触发词时，立即执行此 Skill：
- `执行 context-handoff` / `执行 agent-handoff` / `交接`
- `压缩上下文` / `导出上下文` / `准备切换 Agent` / `给其他 Agent 接手`
- `生成交接文档` / `生成工程上下文包`

---

## 📋 核心指令

触发后，您必须先执行项目类型检测和写入前强制验证，然后将当前工作区的状态编译并输出到 **`.agent_handoff/agent-handoff.zh-CN.md`**（或英文版的 `.agent_handoff/agent-handoff.md`）。

### 0. 项目类型自适应检测 (Before Template Filling)
首先识别当前工程的项目类型，跳过无关的章节以避免文档臃肿：
- **Chrome 浏览器插件**：必须包含平台迁移审计表（API 映射）。可跳过运行时 MCP / Screen 状态等说明。
- **Web 应用 (Web App)**：包含技术栈和部署配置。可跳过 MCP / Screen / Agent 分类章节。
- **命令行工具 (CLI Tool)**：包含入口命令与依赖。可跳过 MCP / Screen / Agent 分类章节。
- **类库 / SDK (Library/SDK)**：包含公开 API 与版本发布策略。可跳过整个运行时状态章节。
- **Agent 插件/工具 (如 OpenCode/ClaudeCode 插件)**：必须保留全部章节。

### 0. 写入前强制验证门 (Pre-Write Verification Gate - 必须执行)
在正式编译或向 `.agent_handoff/` 写入任何内容之前，您必须执行以下验证命令，将您的交接声明与代码库事实进行核对：
1. **事实证据核对**：对于每一句“已实现 X”或“支持 Y”的描述，必须在代码库中进行 `grep` 检索。若检索匹配结果为零，必须将其归为 `📋 规划中`（零代码）或 `🔄 进行中`，绝对**禁止**写为 `✅ 已完成`。
2. **物理行数核对**：对所有准备列出的变更文件执行 `wc -l` 统计真实行数，禁止使用估计值。
3. **函数/符号存在性验证**：文档中提及的所有关键函数和类名，必须在代码中进行 `grep` 验证以确保其真实存在。
4. **平台耦合 API 扫描**：对 `chrome.*`、`localStorage`、`process.env` 等平台专属 API 进行扫描，以真实记录平台耦合度。

### 0. 持续白板同步与规则自我进化 (对话式动态记忆体)
为确保交接上下文作为人机协作的“活白板”：
1. **持续白板同步**：在当前对话回合中，只要任务取得进展，您**必须立刻**更新 `.agent_handoff/current-task.zh-CN.md`（勾选已完成清单、刷新当前焦点）和 `.agent_handoff/decisions.zh-CN.md`（记录最新决策），禁止拖延到会话结束。
2. **系统规则自我进化**：如果在对话中与用户达成了长期性或硬性的编码规约，您**必须立刻修改根目录的规则文件（`.cursorrules` / `.clinerules`）**，将新约束固化到系统级指令中，确保后续回合自动遵循。

### 1. 强制性进度状态前缀
在“已完成内容”与“尚未完成内容”等清单中，每一条描述都必须使用以下前缀之一，禁止不带前缀的状态描述：
- `✅`：已实现（代码在工作区中已存在且通过 grep 验证）。
- `🔄`：进行中（部分代码已存在，需列出已有文件路径）。
- `📋`：规划中（零代码，仅作方案讨论，必须标注讨论或计划日期）。
- `⚠️`：受阻（工作中断或阻塞，必须写明阻塞的具体原因）。

### 2. 废除魔术硬编码数字
在交接描述和验证说明中，**禁止对动态变化的技术指标进行数字硬编码断言**（例如“确保返回 17 个 Agent”、“代码共 200 行”）。必须全部修改为**描述性断言**（例如：“返回 Agent 列表” 替代 “返回 17 个 Agent”）。

### 3. 验证清单推行动态断言
所有的验证命令必须使用动态断言，而非静态行数或内容匹配（例如检查返回的 JSON 体是否非空、HTTP 200、或者包含特定 Key）。

### 4. CLI 工具协同 (推荐优先执行)
如果当前项目安装了 `agent-context-handoff`，你可以直接在终端中运行以下命令来自动收集 Git 状态、解析变更、执行自动化测试并进行 XML 上下文打包：
- 中文交接：`agent-context-handoff --lang zh --focus "下阶段任务目标" --scan --test "pytest" --pack`
- 英文交接：`agent-context-handoff --lang en --focus "Describe the focus" --scan --test "pytest" --pack`

打包或分享前必须运行 `agent-context-handoff lint --dir <project>`。如果发现分支、提交或时间戳已过期，应先复核当前工作区再重新生成。使用 `--mode analysis|fix|review|handoff` 限定接手 Agent 的工作模式。

运行完 CLI 后，您只需手动修改 `.agent_handoff/` 目录下相关文件即可，并引导接手的 Agent 优先读取打包好的 XML 文件（`.agent_handoff/packaged-context.zh-CN.xml`）来极速吸纳上下文。

### 5. 敏感数据脱敏
您必须对生成的内容进行敏感信息扫描和脱敏。将敏感值统一替换为占位符：
- 密钥/Token -> `<REDACTED_SECRET>`
- 密码 -> `<REDACTED_PASSWORD>`
- 私钥 -> `<REDACTED_PRIVATE_KEY>`
- 数据库连接 -> `<REDACTED_PROD_DB>`
- 手机/邮箱 -> `<REDACTED_PHONE>` / `<REDACTED_EMAIL>`
- 内网 IP -> `<REDACTED_INTERNAL_HOST>`
- 会话 Cookie -> `<REDACTED_COOKIE>`

## 📝 交付文档要求

### `.agent_handoff/agent-handoff.zh-CN.md`
必须遵循以下章节布局：
1. **⚡ 接手 Agent 推荐阅读优先级**：引导表格（如：1. 文件清单，2. 架构决策，3. 验证命令，4. 已知问题，5. 当前任务）。
2. **📌 交接元数据 (Metadata)**：生成时间戳、Git Commit SHA。
3. **当前任务**：当前步骤简要目标。
4. **当前状态 (运行时状态)**：Agent 运行时分类、MCP 在线状态、活跃 screen 会话数（非相关项目类型可跳过）。
5. **工程背景与技术栈**：项目简介及核心语言/框架。
6. **相关模块与文件 (物理行数审计)**：包含实际物理行数和职责的对照表格。
7. **核心业务数据流路径与代码跳转**：Mermaid 拓扑流向图与使用仓库相对路径、带行号的代码符号 Step 清单。
8. **跨平台迁移依赖审计**：平台特定 API 引用次数及目标替代技术表格（非迁移或跨平台项目可跳过）。
9. **本轮进度与已完成/未完成清单**：带有 `✅/🔄/📋/⚠️` 前缀的进度清单。
10. **已废弃代码（v1 遗留 / 孤立类）**：无外部引用的孤立类/文件列表。
11. **当前错误 / 阻塞点**：当前遇到的问题或报错。
12. **已确认结论与核心逻辑摘要**：技术决策记录，并附带仓库相对路径形式的源码文件引用。
13. **下一轮焦点 (Focus for Next Session)**：独立章节，描述下阶段具体任务或用户定义的焦点。
14. **已知问题与环境约束**：环境约束和已知的离线服务标示。
15. **验证命令**：包含动态断言的可执行测试命令（避免硬编码数字）。
16. **给接手 Agent 的项目特定硬约束**：包括必须先读的文件、绝对不能改的文件以及代码设计里的逻辑陷阱。
